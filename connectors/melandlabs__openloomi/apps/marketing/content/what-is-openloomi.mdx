# What is OpenLoomi?

> **Your agent can read the update. OpenLoomi helps it understand what changed, what still matters, and what should happen next.**
>
> Open-source, local-first, model-agnostic context runtime. Plugs into Claude Code, Codex, OpenCode, Hermes, and OpenClaw — no need to replace your model or your agent.

**The Attention Agent that runs across every Agent Runtime**

OpenLoomi is the open-source, local-first Attention Agent for developers and small teams building long-lived working agents on Claude Code, Codex, OpenCode, Hermes, and OpenClaw.

It lets your existing agent continuously understand the people, projects, events, relationships, and state changes that span sessions and tools — and writes each step's outcome back into the next context slice.

It turns the day's scattered signals into real decisions, and keeps orchestrating execution until you have a result.

## What is it for?

OpenLoomi gives you a desktop assistant for any Agent framework — Claude Code, Codex, OpenCode, Hermes, and OpenClaw all plug into the same resident desktop.

- **Stop dropping commitments.** Overdue replies, creeping deadlines, "I'll send that follow-up Friday" — and, more importantly, the follow-up three days later that quietly supersedes it. The desktop bubble nudges you, but the system underneath is doing more than recall: it maintains the **current state** of every commitment, with the original message and every transition still auditable. You can extend the signals and decisions it watches for.
- **Find anything from your work life in seconds.** "What did I decide about pricing last quarter?", "Who owns design on Acorn?", "What was I working on before vacation?" — memory spans tools and channels, no more digging through Slack, Gmail, or Notion.
- **Get a morning brief and an end-of-day recap instead of opening nine apps.** The key info lands in one place.
- **Ask AI for work help right inside your chat.** Draft a reply, summarize a long thread, schedule a follow-up — directly in Telegram, WhatsApp, iMessage, QQ, or Lark/Feishu.

See the [Attention Agent](/docs/attention-agent) doc for the always-on companion that surfaces those reminders, or browse [Use cases](/docs/use-cases) for end-to-end workflows.

## Why It Is Different

**OpenLoomi is open-source and neutral.** Instead of locking you into a single vendor's agent, it integrates with any Agent Runtime — Claude Code, Codex, OpenCode, Hermes, OpenClaw — and brings a shared, cross-agent layer to all of them: a resident desktop **attention agent**, **holistic context memory**, **platform connectors**, and **proactive tasks**. Whichever agent you run, OpenLoomi watches the door, remembers what matters, and surfaces only the decisions worth your time — so you spend your attention on the work, not on chasing it.

Explicit, on the record — so the framing is clear before you read the rest of the page:

- **Not an LLM.** OpenLoomi doesn't ship a model. It routes prompts to your existing Claude / OpenAI / local runtime. See [Getting Started → AI Configuration](/docs/getting-started#ai-configuration).
- **Not a replacement for Claude, Codex, or any other agent.** OpenLoomi is a context runtime that sits behind them as a [plugin or skill](/docs/plugins). Your agent stays in charge.
- **Not another agent framework.** It doesn't compete with Claude Code, Codex CLI, OpenCode, Hermes, or OpenClaw — it complements them. See [Agent Runtimes](/docs/reference/agent-runtimes).
- **Not a RAG library.** Retrieval-augmented generation finds similar text. OpenLoomi maintains the **current state** of your work and surfaces transitions, not just similar documents. See [Memory → How this differs from RAG, vector memory, and chat history](/docs/memory#how-this-differs-from-rag-vector-memory-and-chat-history).
- **Not a knowledge graph in the classical sense.** There is no upfront schema, no ontology to maintain. Connections emerge from use (Hebbian-style) and decay when unused. See [Memory → Spatial Dimension: Hebbian Memory Connections](/docs/memory#spatial-dimension-hebbian-memory-connections).
- **Not chat-history memory.** A flat log of past turns can't tell you that "pushing to next week" superseded "I'll have it Friday" — and a tracker that holds both as facts is worse than no tracker. OpenLoomi models commitments as a [state machine with supersession](/docs/memory#commitment-lifecycle).
- **Not a generic automation or notification tool.** It does not "remind you of things." It surfaces [decision cards](/docs/loop) backed by attributable evidence and waits for your Approve before any external action.

| Compared with...                            | OpenLoomi adds                                                                                                                                                                                                          |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Claude Code / Codex / OpenClaw / Hermes** | a **state-aware context runtime** that plugs into your existing agent shell — no model swap, no framework lock-in. See [Memory → Commitment Lifecycle](/docs/memory#commitment-lifecycle) for what "state-aware" means. |
| RAG / knowledge bases                       | work state, not just document retrieval: what changed, what is still true, and what should affect the next action                                                                                                       |
| Chat-history memory                         | attributable, time-bounded, **supersedable** state with source evidence — not just a flat log of past turns. See [Connectors → Trust Ladder](/docs/connectors#trust-ladder-how-access-is-earned) for the access model.  |
| Claude Cowork-style agents                  | the open-source, local-first counterpart that **maintains the state** of commitments (not just their memory), with explicit supersession and Approve-before-action. [Learn more →](/docs/attention-agent)               |

## Deep Dive

### 🐾 Attention Agent — Your Always-On Desk Companion

It's 9 AM — you've just sat down at your desk, your inbox isn't even open yet, and the little fox (Loomi) in the bottom-right of your screen pops up a bubble: "Sarah's meeting invite still needs an RSVP — due by 11 AM today." That's the Attention Agent. It doesn't steal your focus; it just gently nudges you in the moments that matter.

- 🪟 **An always-on-top, transparent little fox** — 168×168, doesn't disappear when you close the main window, hides in the system tray and comes back with a single click.
- 🔔 **Only surfaces when it should** — an email that needs a reply, a meeting past its RSVP deadline, 9 AM rolling around — a single gentle nudge, nothing more.
- ✋ **You can interact with it directly** — click to open details, drag it anywhere on screen, right-click to pause, double-click to summon the main window.
- 🎭 **Sleep mask, wagging tail, little hops** — rich expression animations make it feel "alive" rather than a cold notification.

### 🔄 Loop — Scans Your To-Dos Every 10 Minutes

At the start of the day, what you really want to know isn't "how many unread emails do I have", but "what do I actually have to personally handle today". That's exactly what Loop is for. Every 10 minutes it picks out the signals scattered across your email, calendar, PRs, and @mentions, prioritizes them, and turns them into "decision cards" placed in front of you — you glance at the preview, agree, tap "Approve", and Loop acts on your behalf.

- 📥 **See** — pulls signals from email, calendar, GitHub, Slack, and Linear that are relevant to you
- 🧠 **Understand** — uses OpenLoomi memory to add context to each signal (who the sender is, which project, what you last discussed)
- 🪪 **Decide** — tags each signal with a type (`email_reply` / `rsvp` / `review_pr` / `im_reply` / `todo`) and a confidence score
- 🛡️ **Protect** — Dry-run always comes first, **execution always waits for your Approve**

## A Complete Intelligence Loop: From Perception to Action

OpenLoomi implements a full **"Receive → Process → Remember → Understand → Serve"** loop — mirroring how a capable human colleague operates:

<img
  src="/img/openloomi/components.png"
  alt="The OpenLoomi intelligence loop — Receive multi-platform input, Process / denoise, Remember knowledge graph, Understand semantic; together driving proactive Action (summary / auto-reply / scheduled reports / deadline)"
/>

| Layer             | What It Does                                                                                                                       |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **📡 Receive**    | Multi-platform, multi-modal ingestion — IM, email, documents, files, web data, voice calls — unified into one pipeline             |
| **⚙️ Process**    | Noise reduction at scale — deduplication, OCR, ASR, intent extraction, semantic clustering — turning chaos into structured signals |
| **🧠 Remember**   | Persistent knowledge graph — people, projects, decisions — survives conversations, platforms, and months of time                   |
| **🎯 Understand** | Deep semantic intent, not just keywords — cross-modal understanding, emotional tone, contextual relevance                          |
| **🚀 Serve**      | Proactive delivery — smart summaries, auto-replies, scheduled reports, personalized alerts — without being asked                   |
